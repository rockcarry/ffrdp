# ffrdp 性能评测报告（模板）

> **用法** ✓：复制为 `docs/perf-eval-ffrdp-v<版本>.md`，把 `⟨…⟩` 换成实测值。
> 数据来源：`bash tools/perf-eval.sh` 的 `logs/perf-<stamp>/`（`summary.md` / `results.csv` / `base.csv` / `base-bidir.csv`）
> 分布统计：`bash tools/perf-stats.sh logs/perf-<stamp>` ⇒ `detail.csv`
>
> **口径铁律**（写数字前先确认这四条，否则数字之间不可比 ✗）：
> 1. 吞吐 = `total_send / conn age`（每连接）；多连接另给**合计** ✓
> 2. resend / rtts **分方向**：上行取客户端日志、下行取服务端日志（同一侧三项同源 ✓）
> 3. 分布：**单连接** = 12 次 dump 的时间序列（吞吐用区间差分，n=11/10）；**多连接** = 每条连接最后一次快照（n=`CLIENTS`）；方差为**总体方差**
> 4. CPU **不按方向**（它是"端"的指标），但**有分布**：`cpu_loop` 每秒采一个点，输出 min/max/avg/σ² ✓
>    ⚠ CPU 只含进程 `utime+stime`，不含 softirq / host 侧（WSL2 下尤其明显）⇒ 不能用来比"谁更省 CPU" ✗

## 十二、已知边界

- CPU 是「端」的指标，**不按方向**分；且只含进程 `utime+stime`（不含 softirq / host 侧，WSL2 下尤其明显）⇒ 别用总分比"谁更省 CPU" ✗
- 单连接 n=11、多连接 n=`CLIENTS`，样本量只够看"这一档抖不抖"，不能代表长期稳定性 ✗
- 多连接的 resend/rtts 与 `summary.csv` 可能差 ±1 点（块选择逻辑不同）⇒ 以 `detail.csv` 为准 ✓
- 跨轮 md5 必然不同（`__DATE__/__TIME__` 编进版本串）⇒ 跨轮只比趋势 ✗
- 未覆盖：⟨IPv6 / 漫游 / 长稳 / 吞吐档 / FEC⟩
