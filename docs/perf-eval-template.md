# ffrdp 性能评测报告（模板 v2.1）

> **用法**：复制为 `docs/perf-eval-ffrdp-<版本或日期>.md`，把 `⟨…⟩` 换成实测值。
> **表格不要手写** —— 手抄一次就会有一次口径漂移（上一版踩过两次：`TCP both 档 -/- 被当成 0`、
> `lo 下行全被写成 0`）。全部由脚本从原始日志现算：
>
> ```bash
> bash tools/perf-stats.sh  logs/perf-⟨a⟩ logs/perf-⟨b⟩ logs/perf-⟨c⟩   # ⇒ 每轮 detail.csv
> bash tools/perf-tables.sh logs/perf-⟨a⟩ logs/perf-⟨b⟩ logs/perf-⟨c⟩   # ⇒ 六张表（直接贴进本文）
> ```
>
> **口径铁律**（写数字前先确认，否则数字之间不可比 ✗）：
> 1. 吞吐单位 **MB/s = 10⁶ B/s**（不是 MiB/s）。iperf3 的 `Gbits/Mbits ÷ 8` 正好是同一口径 ✓
> 2. **单元格 = `avg±std`**。单连接 std = 时间序列标准差；多连接 std = 15 条（每条先取时间均值）的横截面标准差
> 3. **丢首区间**：单连接/iperf 区间均值都丢掉第一个 5 s（含握手与慢启动爬坡）⇒ n = 区间数 − 1
> 4. resend / waste / rtts **分方向**：上行取客户端日志、下行取服务端日志（同一侧同源 ✓）
> 5. CPU 是「端」的指标（不分方向），只含进程 `utime+stime`，**不含 softirq / host 侧**（WSL2 下尤其明显）
>    ⇒ 别用总分比「谁更省 CPU」✗；低速率档还会被测试程序的忙等 send 循环污染（见附录 B）

## 二、测试环境与基线

| 环境 | 链路 | iperf3 单向 上/下 | iperf3 双向 上/下 | ping 空载 avg/max | 负载 ping（TCP 跑满时） |
|---|---|---|---|---|---|
| `lo` | 本机回环（MTU ⟨65536⟩）| ⟨7300 / 7162⟩ MB/s | ⟨4062 / 3612⟩ | ⟨0.05 / 0.06⟩ ms | ⟨0.02 ms⟩ |
| `slow` | ⟨AP / 路由器限速⟩ | ⟨0.38 / 1.01⟩ | ⟨0.35 / 0.72⟩ | ⟨6.3 / 12.3⟩ | ⟨1431 / 586 / 1151⟩（上/下/双向）|
| `fast` | ⟨AP / 信道⟩ | ⟨11.66 / 11.05⟩ | ⟨⟩ | ⟨5.2 / 21.7⟩ | ⟨82.8 ms，丢包 3.3%⟩ |

> ⚠ **换了 AP/网口就必须重测基线**：同一份报告里，「快 AP」从 28.25 MB/s 变成 11.66 MB/s（≈100BASE-TX 线速）
> 这种环境漂移，会让上一轮的所有相对值失效 ✗。
> ⚠ `lo` 的 iperf3 是**内存回环**（58 Gbits/s ≈ 7.3 GB/s），与 ffrdp 的 55 MB/s 差 130 倍是正常的：
> 差在「每次 syscall 搬多少字节」（64 KiB vs 1280 B），不是带宽 ⇒ **lo 只做自比，不做吞吐验收**。

## 九、已知边界

- 单连接 n=⟨22⟩ 个区间、多连接 n=`CLIENTS`：样本量只够看"这一档抖不抖"，不代表长期稳定性 ✗
- CPU 不含 softirq/host 侧；低速率档受测试程序忙等污染（`send refused by gate` 上万次）⇒ 只做相对比较
- `lo` 的 iperf3 是内存回环，不能当"链路容量"
- 非对称档 TCP 侧是**两条顺序跑的单向流**（`--bidir` 做不到一侧 80% 一侧 20%），与 ffrdp 的单连接双向不同构 ⇒ 只比量级
- 未覆盖：⟨IPv6 / 漫游 / 长稳 / FEC / 256 档⟩
