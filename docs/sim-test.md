## 它解决什么问题

真机测量**跨轮次不可比** ✗：同一条链路在不同时刻的丢包/乱序/负载都不同，
所以"这次 2.3%、上次 2.9%"分不清是代码变了还是链路变了 ✗。

这个仿真把网络**确定化**：虚拟时钟 + 由包头序号 hash 决定的丢包/抖动 ⇒
**两次运行面对的网络逐字节相同** ✓ ⇒ 把"老代码"和"新代码"放在同一条假链路上跑，
**差异就一定是代码造成的** ✓（噪声为 0，不是 ±50% ✓）。

## 怎么跑

```bash
bash tools/sim/run.sh                    # 跑全部（14 个测试 + hs-e2e / e2e-raw / e2e 三个场景组 ✓）

ASAN=1 bash tools/sim/run.sh             # 同一套判据再跑一遍：带地址消毒剂、并自动关 ASLR ✓
                                     # 内存类 bug 只有这一遍才露 ✓（真机上踩到的三个都是这样抓出来的 ✓）；
                                     # 现在它是**例行判据**的一部分 ✓ —— 改完必跑 ✓。
TESTS="e2e"  bash tools/sim/run.sh       # 只跑端到端
TESTS="t_rto" bash tools/sim/run.sh      # 只跑 RTO 放大测试
bash tools/check.sh                     # **一条命令跑完全部判据** ✓（编译 + 仿真 + ASAN + 本机两进程 + v1 互通 ✓）
REF=/path/to/old_ffrdp.c bash tools/sim/run.sh   # 基线不用 git HEAD，而用指定文件
```

| 环境变量 | 含义 | 默认 |
|---|---|---|
| `TESTS` | 要跑哪些测试 / 场景组（可多选，空格分隔）| `t_rto t_pseudo t_cwnd t_ack t_fuzz t_peer t_handshake t_crypto t_recvdata t_readpath t_keepalive t_init t_dump t_fec hs-e2e e2e-raw e2e` |
| `REF` | **基线**源码路径 | `git show HEAD:ffrdp.c` |
| `ASAN=1` | 打开地址消毒器（并自动加上 `halt_on_error=1` 与 `setarch -R` ✓）| 关 |
| `SIM_LL_DEADLINE=1` | 假 lowlevel 换**忠实模型**（只在"有帧到"或"期限到"时唤醒 ✓）⚠️ 丢包场景下很贵 ✗，见下文的实测 | 关 ⇒ 用旧模型（每步无条件一次 TIMER ✗）|
| `SIMLOG` | 逐行日志写到哪个文件 | `/tmp/ffrdp-sim-harness.log` |

**被测版本恒为工作区当前 `ffrdp.c`** ✓ —— 所以典型用法是：改完代码直接 `bash tools/sim/run.sh`，
看"对比 HEAD 有没有变化" ✓。

依赖只有 `gcc` 和 `bash` ✓，**不需要网络** ✓（`sendto`/`recvfrom`/`select`/`calloc`/`free`
都用 `-D` 换成了仿真实现 ✓）。

## 它是怎么做到的（读代码前的 30 秒）

1. **时钟虚拟化**：`run.sh` 把 `utils.c` 里**整条**
   `uint32_t ms = ((uint32_t)ts.tv_sec * 1000 + ts.tv_nsec / 1000000);` 换成 `uint32_t ms = sim_tick();`
   （生成 `utils_sim.c` ✓，并断言替换成功 ✓）⇒ 时间由 `sim_tick()` 驱动，**1 步 = 1 ms** ✓。
   ⚠️ 必须按**整条形状**匹配 ✓：只认 `ts.tv_nsec` 的松匹配曾经改掉一条注释、把裸语句留在文件作用域 ✗。
2. **两台实例**：`e2e.c` 起两个 `ffrdp` 上下文（side 0 / side 1），形状与 `test.c` 相同 ——
   每步各自投喂一个 1..`maxchunk` 字节的随机块 ✓；**"驱动一步"按被测版本分两种** ✓：HEAD 侧调 `ffrdp_update()` ✓，
   工作区侧**由假 lowlevel 驱动**（`sim_ll_run()`：先把已排队的包逐个走 RECV ✓，再走一次 TIMER ✓）——
   与真传输的一圈同形 ✓。开关 `SIM_LL_DEADLINE=1` 换成忠实模型：只在"有帧到 / 期限到"时唤醒 ✓（默认模型每步无条件 TIMER ✗ ⇒
   判"唤醒是否正常"必须打开这个开关 ✗）。
3. **假网络**（`simnet.c`）：**每个 slot 一个内存队列**（默认就是 side 0 / 1 两个 ✓），提供丢包、连丢、延迟、抖动、
   **共享限速器（shaper）**、**令牌桶（policer）**、**重尾尖峰（spike）** ✓。
4. **内存记账**：`calloc/free` 被计数 ⇒ 输出里的 `leaked=` 是**真正的泄漏** ✓（应当恒为 0 ✓）。
5. **两侧各一份头文件 + 按形状决定开关** ✓：两侧各自生成 `ffrdp_base.h` / `ffrdp_new.h` 与
   `lowlevel_base.h` / `lowlevel_new.h` ✓（API 与 vtable 正在变 ✗ ⇒ 两侧不能共用一个头 ✓）。
   开关也**按源码形状**判 ✓：`counter_ack_recv` / `counter_recv_ooo` / `counter_recv_dup` / `counter_rto_spurious` /
   `counter_ooo_d1_24` … ⇒ `-DNEW_COUNTERS` / `-DRECV_OOO` / `-DDUP_REPORT` / `-DSPUR` / `-DOOO_HIST` / `-DHAVE_INFLIGHT` ✓；
   还有 API 形状（`timeout_ms` / `addr` 形式的 `ffrdp_init` ⇒ `-DFFRDP_API_HAS_TIMEOUT` / `_HAS_ADDR` ✓）
   与**是否由 lowlevel 驱动**（`-DFFRDP_LL_DRIVEN` ✓），以及**结构是否已拆出每连接层**
   （`FFRDPCONN` ⇒ `-DCONN_SPLIT` ✓ —— 拆分后连接级字段挂在 `ctxt->conn` 下 ✓，测试统一写成 `CONN(c)->字段` ✓，
   两侧都能编 ✓）⇒ **同一份测试能同时编译老源码和新源码** ✓（这是能做 A/B 的关键 ✓）。

> 生成的中间文件（`ffrdp_base.c`、`ffrdp_new.c`、`ffrdp_*.h`、`lowlevel_*.h`、`utils_sim.c`、`*_base`、`*_new`、`*.o`）
> 都在 `.gitignore` 里 ✓ —— 它们不是源码，每次 `run.sh` 都会重写 ✓。

## 十四个测试

| 测试 | 内容 | 判据 |
|---|---|---|
| `t_rto` | 12 个同时过期的帧被逐个重传，观察 RTO 被放大多少次 | 期望"**每往返退让一次**"⇒ `rto_backoff` 只有 1 次，而不是 12 次 ✗ |
| `t_pseudo` | **伪超时**：ACK **晚到**但一帧没丢 —— 发两帧、只确认第一帧、让第二帧自己到点（等待期间确实收到过 ack ✓，所以它是伪超时 ✓）| ① 确实发生了 RTO 重传（否则没测到东西 ✗）；② 被认成伪超时（`counter_to_hadack >= 1` 且 `counter_to_noack == 0` ✓）；③ **cwnd 没有被拉回 1** ✓（对照 `t_rto`：那里 ack 根本不来 ⇒ 仍应打回 1 ✓）|

### 多对端：夹具 API（P0 新增）

为 v2 的"**一个 lowlevel 服务 N 个对端**"做准备 ✓。夹具里**一个 slot = 一端**，地址是可选的 ✓：

| API | 作用 |
|---|---|
| `sim_slot(idx, addr)` | 登记 slot `idx` 自己的地址 ✓（不登记 = 0 ⇒ 包不带源地址，与以前逐字相同 ✓）|
| `sim_send_from(dst, src, buf, len)` | 显式发：**目的 slot + 包里带的源地址** ✓（多对端用这个 ✓）|
| `sim_recv_src()` | 最近一次 `sim_recv` 取到的包的源地址 ✓（0 = 旧路径 ✓）|
| `sim_ll_route(fl, addr, slot)` | 假 lowlevel 的**按地址路由**：`ll->send(addr)` 落到哪个 slot ✓ |
| `sim_ll_own(fl, addr)` | 本实例自己的地址（回给已登记对端时带的源地址 ✓）|

**地址约定（P2 第二步起生效 ✗→✓）**：协议把地址表示成 `(ip << 16) | port` ✓、并**按地址查表分发** ✓
（`ffrdp_conn_by_addr()` ✓：来源地址不是本连接对端的帧一律丢弃 ✓），所以夹具报的地址
**必须等于协议真算出来的那个值** ✓。默认 `SIMLL_ADDR = ffrdp_addr_make(127.0.0.1, 8001)` ✓
（仿真里所有测试都用 `127.0.0.1:8001` ✓）。**换端口要同步改它** ✗ ——
实测把它改错一位：对端方向 **100% 丢包** ✓、`resend=140%` ✓、客户端 `recv` 掉到 1/40 ✓。
`e2e.c` 用的是更强的做法 ✓：直接把 `c0->peer_addr` 登记给服务端那一侧 ✓（不依赖常量 ✓）。

**关键约定** ✓：`sim_send()` / `sim_recv()` / `msg.addr` 的**老行为一个字都没变** ✗ ——
没登记地址时 `msg.addr` 仍是老常量 `SIMLL_ADDR` ✓、`sim_send()` 仍是"发到 `1-cursid` 那个 slot" ✓
⇒ 老的两端测试一行都不用改 ✓（判据：17 场景输出**逐字相同** ✓，已验 ✓）。
⚠️ **翻默认（`hs` 默认开）之后** ✓：这条判据要在 `E2E_HS=0` 下成立 ✓ ——
   默认那 17 个场景现在走**握手** ✓，统计数字**本来就会变** ✓（有意 ✓，见下面"三个场景组"）。

⚠️ **忠实模型的成本**（`SIM_LL_DEADLINE=1`，同一个 0.05 丢包场景，本机）：
- **修之前** ✗：300 步 **326s**（撞 300 次护栏 ⇒ 每步一次）；6000 步 **84s**（撞 556 次）；
  最硬的场景（`0.02` 丢包 × `burst=6` × 6000 步）HEAD 侧跑到 **7 分 37 秒还在 99.9% CPU 自旋** ✗。
- **修好之后** ✓ —— `ffrdp_next_due` 三处与 tick 对齐（① drain 的早退闸 `wait_snd < FFRDP_MAX_CWND_SIZE` ✓；
  ② 期限只数 tick 看得见的**前 `cwnd` 个表项** ✓；③ `tick_timeout` **恰好等于 now** 的挪 1ms ✓）：
  300 步 **4ms** / 3000 步 **12ms** / **6000 步 18ms** ✓，护栏**全部归零** ✓；
  最硬那个场景修好侧也在**几十毫秒**内跑完 ✓（6000 步：84s → 18ms ≈ 4600 倍）。
- **只改了"什么时候被叫醒"** ✓：同一步数下的交付量（`recv`/`resend`/`cwnd`…）与修之前**逐字一致** ✓，
  干净场景的忠实模型输出也是 **0 差异** ✓。
- ⚠️ **忠实模型只能跑"修好的那一侧"** ✗：`run.sh` 是两侧都跑 ✓ ⇒ 把 `SIM_LL_DEADLINE=1` 套在整个组上时，
  **未修的 HEAD 侧**会在硬场景上自旋 ✓（我自己就踩了这个 ✗）⇒ 忠实用法：先编好两侧，再对 `e2e_new` 逐条跑 ✓。
- 默认模型不受影响 ✓（`next_due` 的返回值在默认模型里**根本没被读** ✓）⇒ 三处改动的 A/B 都是 **0 行差异** ✓。
  这也说明：**这类 bug 默认模型看不见** ✗ —— 留一个忠实模型是有意义的 ✓。

### t_fuzz：敌意输入（端口健壮性的回归）

**它回答的问题**：server bind 了端口，任何人往这个端口发非法数据，进程至少要**不崩** ✓。
这里不关心"对端说谎"（那是协议问题），只关心**陌生人能发什么**。

**为什么 fork**：崩溃就是数据 ✓。每个片段在一个**独立子进程**里跑（建 server 上下文 → 注入 → update），
父进程用 `waitpid` 读状态 ⇒ 一个片段能杀死进程，报告里也只是**一行**，并且**指名是哪几个字节**：

```
  CRASH case  12: SIGFPE (divide by zero?)  len=4 | 00 00 00 00
```

**另外两项检查**：乱序洪泛（洞上方 2000 vs 4000 个帧）看内存是否**有界** ✓ —— 一个受信用额度约束的
实现对端不该越存越多 ✗。

**怎么跑**：

```bash
cd tools/sim
TESTS="t_fuzz" bash run.sh          # HEAD 与工作区各跑一遍（天然 A/B）
ASAN=1 TESTS="t_fuzz" bash run.sh   # 地址消毒器：不崩但越界读也要抓
```

**`halt_on_error=1` 才是这条路的重点**（`run.sh` 已设）：sanitizer 的默认行为是**报完错继续跑** ✗，
而崩溃测试里"继续跑"的那个进程，状态本来就是坏的（能走到这里的那条路径正是"4GB 的 memcpy 砸在
190KB 环形缓冲上"）⇒ 它会在 sanitizer **自己的 handler 里再次 fault** ⇒ handler 递归 ⇒ 同一行
无限刷。实测：默认选项下 90 秒产出 **1.5GB / 5100 万行 DEADLYSIGNAL**（17MB/s ✗）—— 与一次
"无截断重定向到文件"攒下的 **19GB** 完全吻合；同一跑法加上 `halt_on_error=1` 后只有 **469 字节** ✓
（打脆弱版本时 81KB、并正常报出 8 个崩溃 ✓）。

⚠️ **sanitizer 二进制必须关 ASLR** ✓：本机内核上 sanitizer 有时在启动时放不下 shadow memory ✗
（实测：加 ASAN 的 `t_rto` 跑 20 次死 5 次 ✗；只关这一个进程的 ASLR 后 **20/20 干净** ✓）
⇒ `run.sh` 在 `ASAN=1` 时自动给每个 sanitizer 二进制加 `setarch -R` ✓（不需要特权 ✓）。

⚠️ 两条纪律仍然成立：**跑崩溃侧时不要把输出直接重定向到文件**（用 `| head` 或 `timeout`）✗；
**不要加 `handle_segv=0` 这类"看起来更彻底"的开关** ✗ —— 实测它们会让整跑在第一个崩溃处直接
死掉、反而报不出崩溃 ✓。

**判据**：`all 398 fragments survived` ✓ ＋ `flood above a hole: … -> bounded` ✓。
修 `ffrdp.c` 之前是 `33 of 398 fragments killed the context` ✗ ＋ `-> UNBOUNDED` ✗（见 `notes.md` 12）。

### e2e 的参数（12 个，位置固定，都有默认值）

```text
./e2e_new  loss burst delay jitter steps maxchunk  [cap qmax [pcap pburst [spike% spike_ms]]]
           └────────── 最常用的前 6 个 ──────────┘    └──────────── 后 6 个可选 ────────────┘
```

| # | 参数 | 默认 | 含义 |
|---|---|---|---|
| 1 | `loss` | `0.0` | 丢包率（`0.05` = 5%）|
| 2 | `burst` | `0` | 连丢个数（`0` = 随机丢；`6` = 一次丢 6 个）|
| 3 | `delay` | `4` | 单向延迟 ms |
| 4 | `jitter` | `0` | 抖动 ms（回显里写作 `jit`）|
| 5 | `steps` | `6000` | 仿真步数（1 步 = 1 ms ⇒ 默认跑 6 秒）|
| 6 | `maxchunk` | `8192` | 每步最多投喂的字节数 |
| 7 | `cap` | `0` | 共享限速器速率 KB/s（`0` = 不限速）|
| 8 | `qmax` | `0` | 限速器队列 KB（超出即丢）|
| 9 | `pcap` | `0` | 令牌桶速率 KB/s（只作用于 side 0 的上行；超速即丢、不排队）|
| 10 | `pburst` | `0` | 令牌桶深度 KB |
| 11 | `spike%` | `0` | 被"重尾"命中的包比例（%）|
| 12 | `spike_ms` | `0` | 重尾额外延迟 ms |

> 都是**位置参数** ⇒ 要给后面的，就得把前面的都写全（不能跳）✓；日常只看前 6 个 ✓。

`shaper` 与 `policer` 的区别值得记住：**shaper = 排队（延迟上升）**、
**policer = 丢弃（超量直接丢）** ✓ —— 真机链路上的限速往往两者混合 ✓。

### 三个场景组：`e2e` / `hs-e2e` / `e2e-raw`

| 组 | 是什么 | 用途 |
|---|---|---|
| `e2e` | 17 个场景，**不给 hs 键** | 现在走的就是**握手路径**（v2 默认 ✓）⇒ 新判据 ✓ |
| `hs-e2e` | 4 个场景，同样不给 hs 键 | 握手路径的**快速**组（开发时用 ✓）|
| `e2e-raw` | 4 个场景，`E2E_HS=0` ⇒ `hs:0` | **老路径的回归网** ✓：输出应与"翻默认之前"**逐字相同** ✓ |

- ⚠️ `hs` **默认已翻成开** ✓（v2 起）⇒ 任何"以为没握手"的判据都作废 ✗。要跑老路径必须显式 `hs:0` ✓；
  `t_rto` / `t_ack` / `t_fuzz` 这三个单连接测试就是显式 `hs:0` 的 ✓（它们测的就是老路径 ✓）。
- `E2E_HS` 三态：`1` 强制握手 ✓ / `0` 强制老路径 ✓ / 不设 ⇒ 跟随协议默认 ✓。
- 为什么值得留着 `e2e-raw` ✓：翻默认这类改动，"没碰老路径"必须**能用字节证明** ✓，而不是靠读代码相信 ✓。

## 输出怎么读

每次运行打印下面这些行，**顺序固定**：

```text
       rto_floor=142 ms (the peer called 24 of our retransmits pointless)
loss=0.000 burst=0 delay=4 jit=1 cap=1200KB/s q=200KB pol=0KB/s/0KB spike=0%/0ms |
c0 recv=  4.75MB resend= 0.61% (rto   24 fast    0) cwnd=64 ssth=32 wait=255 fail=5222 rttd=6 |
c1 recv=  1.88MB resend= 3.44% maxrto=0 leaked=0
       c0 ack_recv=… mack=… hole=… timeout_evt=… rto_backoff=… | peer recv_ooo=… recv_far=… | dup=… ack_dup=…
       c0 spur=… rto_floor_raises=…
       c1 ooo dist 1..24=… 25..64=… 65..128=… >128=… | mack bits sent(c1)=… recv(c0)=…
       air loss c0->c1=0.00% (…/…)  c1->c0=0.00% (…/…)
       c0 inflight=…
```

两点阅读提示：

- **第 1 行与第 5 行之后那几行是"可选"的** ⇒ 源码里带对应计数器时才会打印（老源码会少几行，这是正常的 ✓）；
- **第 2~4 行工具实际打印成一行**（很长，编辑器里会折行）—— 这里只是在 `|` 处断开，方便逐段对照下表 ✓。

### 字段

| # | 字段 | 含义 |
|---|---|---|
| ① | `loss burst delay jit cap q pol spike` | **场景参数回显**（与命令行一致 ⇒ 可核对"跑的确实是这个场景"）|
| ② | `c0 recv resend (rto/fast) cwnd ssth wait fail rttd` | **c0 → c1 方向**：`recv` = c1 实收字节；`resend` = **c0** 的重传率；`(rto/fast)` = 两类重传次数；`wait` = 应用排队峰值；`fail` = 发送失败次数 |
| ③ | `c1 recv resend maxrto leaked` | **c1 → c0 方向**（对称）；`maxrto` = 撞到 RTO 上限的次数；`leaked` = 未归还的分配数，**必须为 0** ✓ |
| ④ | `rto_floor=… (the peer called N …)` | 本端当前 RTO 下限 ms，括号里是**对端报告"我们有多少次重传是白费的"** ✓ |
| ⑤ | `ack_recv mack hole timeout_evt rto_backoff` | c0 侧 ACK 统计：收到多少 ACK / 其中带位图的 / 报出"洞"的 / 超时事件 / RTO 退让次数 |
| ⑥ | `peer recv_ooo recv_far` | 对端看到的**乱序**与"远乱序"（超出 24 位掩码、报不回去的那一类 ✓）。注意 `recv_far` 的边界是 `dist > 23`，比掩码本身**严一帧**（`dist 24` 其实装得下 ✓）|
| ⑥b | `c1 ooo dist 1..24 / 25..64 / 65..128 / >128` + `mack bits sent / recv` | **距洞多远**（四档之和 = `recv_ooo` ✓）与 **mack 位数**（`sent` 与 `recv` 的差 = 报告丢在路上 ✓）。档位决定"加宽掩码值不值、加多宽"，位数看"报告有没有送到" ✓（旧源码只有前两档，汇总行会短一点 ✓）|
| ⑦ | `dup ack_dup` | 对端**实际收到**的重复帧数 / 它**报回来**的数量 ✓ |
| ⑧ | `spur rto_floor_raises` | 伪超时次数 / 下限抬升次数（可选）|
| ⑨ | `air loss c0->c1=… c1->c0=…` | **真实空口丢包率**（发送帧数 − 收到帧数）⇒ 用来核对"场景的丢包率是否如实生效" ✓ |
| ⑩ | `c0 inflight=…` | 结束时的在途帧数（可选，闸门相关）|

### 读的三步

1. **先确认场景**：① 与命令行一致、⑨ 与设定的丢包率量级相符 ⇒ 否则这次运行不作数 ✗；
2. **再看 A/B**：同一场景下 HEAD 与 work 两行**成对出现** ⇒ 直接比 ② / ③ 的 `recv`（交付量）与 `resend`（重传率）✓；
3. **有疑点才看诊断行**：⑤⑥⑦（`mack`/`hole`/`ooo`/`dup`）用来解释"为什么变了" ✓。

## 使用纪律（这几条是踩出来的）

1. **干净链路必须"逐字不变"** ✓ —— 任何改动只要动了场景 1/2 的输出，就先当成回归查 ✗。
   （**翻默认之后**：这条纪律落在这个范围内 —— 老路径看 `e2e-raw`（`hs:0`）**逐字不变** ✓；
   握手路径 `e2e` 的统计数字会变 ✓ ⇒ 它的判据看**判定行**（丢包容差 / 泄漏 / 握上手就必须真传数据 ✓），
   而不是看 `recv` 的小数点 ✓。）
2. **不要用单个小场景判"退化"** ✗ —— 同一族代码只改 RTO 逻辑就能让某个场景的结果跳 8 倍
   （1ms 量化 tick + 队列耦合 ⇒ 混沌 ✓，详见 `notes.md` 末尾"判据的坑"）。
   **要看"场景族的趋势"**（例如"丢包族一致退步"才是真信号 ✓）。
3. **仿真验证不了的两类改动** ✗：
   - **乱序相关**（本仿真没有乱序模型 ⇒ 快重传纪律只能在真机验证 ✓）；
   - **收窄在途量**（仿真的 ACK 粒度比真机粗 ⇒ 小窗口在仿真里会直接断流 ✗ ⇒ 只能看真机 ✓）。
4. **判据的顺序**：仿真判"**没有回归**" ⇒ 真机判"**确实有收益**" ✓ ——
   两者缺一不可，任何一步不过就不要上机 ✗（`ffrdp-v1.md` §2.3.4 里的 step27 就是仿真不过而放弃的例子 ✓）。

## 局限（诚实列出）

- **无乱序模型**：帧要么丢要么按 FIFO 顺序到 ✓ ⇒ 与乱序有关的收益/风险测不出来 ✗。
- **ACK 粒度较粗**：窗口小到一定程度仿真会断流 ✗（真机不会 ✓）。
- **1ms 时间量化**：短 RTT 场景的时序与真机不完全可对应 ✗ ⇒ 别用它推断绝对时延 ✓。
- **没有真实密码学**：`t_crypto` 用可逆字节异或占位 ✓ —— 它验的是**加密回调的接线与对称性** ✓
  （协议原样交付载荷、两条出口都挂上 ✓），**不验**任何算法的强度 ✗；也没有真实 socket 语义 ✓。
  （协议状态机与拥塞控制逻辑才是仿真的目标 ✓。）
